# IMP-20260814-05 — v15 phase separation

- ID: `IMP-20260814-05`

- Classification: architecture / lifecycle / context quality / verification
- Risk: high (cross-cutting lifecycle migration)
- Approved: 2026-08-14, explicit user approval

## Problem

The user wants Planning to concentrate on ideation/brainstorming, Design to concentrate on detailed solution design and implementation-ready refinements, Development to implement/test/verify the approved design, and release/operations to keep the existing behavior. v14.9.4 already contains these capabilities but mixes working phase, approval milestone, artifact readiness, and agent permission in several state names and workflows.

## Assumptions

- v14.9.4 is the source version.
- Existing safety, verification, Codex/Cursor fallback, GitHub, CodeRabbit, React Doctor, release, incident, MCP, and human-production controls must not be weakened.
- Existing task `plan.md` may be evidence-bound and therefore must remain readable rather than being blindly renamed.

## Research basis

Primary sources reviewed before implementation:

- Cursor documentation for persistent Rules and Agent Skills / dynamic procedural context.
- OpenAI Codex documentation for subagents and bounded delegation that keeps the main conversation focused.
- GitHub Spec Kit documentation for specification-driven separation between specification/design and implementation.

The project does not depend on any of those products for lifecycle correctness; the local manifest/schema/gate system remains the source of truth.

## Proposal / accepted design

- Separate Phase, Gate, Artifact, and Agent concepts.
- Project: `MIGRATION_PENDING → PLANNING → DESIGNING → ACTIVE` plus terminal `RETIRED`.
- Project gates: planning, stack, architecture, design.
- Task: `DESIGNING → DEVELOPING → VERIFYING → REVIEWING → DEPLOY_READY → DONE`.
- Task gates/evidence: scope approval, design approval, implementation, verification, review, release approval.
- Bind Development to a hashed Design Baseline.
- Make Planning/Design conversation-first and keep code writes out of those phases.
- Keep v14 release/incident behavior.
- Provide v14.9.4 migration and legacy `plan.md` compatibility.

## Acceptance

- No v14 approval/safety capability is removed merely to simplify state names.
- New state/gate schemas validate and lifecycle transitions are deterministically tested.
- Development refuses missing/stale design approval and mismatched design baseline evidence.
- Rework can return to Design and invalidates downstream evidence.
- Canonical phase Skills generate without stale retired Skill projections.
- Existing release/incident/security/profile/CI controls continue to pass regression checks.
- Migration is reversible and does not fabricate approval evidence.
