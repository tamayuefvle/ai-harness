# IMP-20260814-02: Overlay package metadata verification

- ID: `IMP-20260814-02`
- Status: `done`
- Date: 2026-08-14
- Owner: human / implementer

## Problem

After a product takes ownership of its live `package.json`, harness verification incorrectly requires the distribution package name, version, private flag, and exact script and development-dependency maps.

## Proposal

Use `package.json.name === "ai-harness"` to identify the shipped substrate. Keep its exact contract, while product overlays retain a merge contract that requires every harness fragment entry unchanged and allows product metadata and additional entries.

## Acceptance

- The shipped substrate remains fail-closed for identity and exact fragment drift.
- An overlay with all fragment entries and additional product fields passes.
- Missing or changed fragment scripts or harness development dependencies fail.
- Harness document headings remain version-checked for both modes.

## Verification

- `node --test scripts/harness/package-substrate.test.mjs scripts/harness/check-current-version.test.mjs`
- `npm run verify:harness`（264 tests passed; overlay mutated `devDependency` coverage added after review）

## Outcome

The package contract now distinguishes substrate identity from overlay merge verification. Version metadata and user guidance are synchronized for v14.9.2.
