# Ship harness npm substrate in the distribution

- ID: `IMP-20260813-02`
- Status: `done`
- Date: 2026-08-13
- Owner: harness maintainer

## Problem

The distribution GitHub repository has no `package.json`, so after the root commit CI classifies as `invalid` (`post-bootstrap-project-metadata-missing`). That blocked ordinary PRs even though the failure is unrelated to product stack.

## Proposal

Ship a private harness substrate synchronized from package fragments. Keep overlay merge-not-replace for existing applications. Skip unresolved `profile:check`, and keep Playwright/React Doctor off until those profiles are selected.

## Acceptance

- Distribution checkout is CI `ready`: `package.json` + `package-lock.json`.
- Substrate `private: true`; scripts/devDependencies match fragments; version matches `PACKAGE_MANIFEST.json`.
- Existing-app overlay docs forbid overwriting application package metadata.
- Unresolved profile resolution does not fail `verify:ci`.
- React Doctor is not default-on for empty profile lists.

## Verification

`npm run verify:harness` on this checkout: 249 tests passed. `ci-project-state.sh` reports `ready` with `package-lock.json`. `profile:check` skips while resolution is unresolved.

## Outcome

Shipped private substrate at v14.8.0. Overlay docs forbid overwriting application package metadata. Ajv `strictTypes` schema compile now succeeds. E2E/React Doctor remain profile-gated. Independent Codex review: `approve-with-nits` (E2E workflow condition tests tightened).
