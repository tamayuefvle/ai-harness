# IMP-20260805-02 — v10.1 fail-closed evidence repair

## Request

After the v9-to-v10 consistency audit identified lifecycle evidence bypasses, implement the approved Schema-driven repair, validate it independently, and package a corrected harness.

## Classification

- Type: defect correction, security/integrity hardening, schema contract unification, CI cost correction
- Scale: cross-cutting
- Initial risk: critical
- Approval: user instruction `修正実行して。` on 2026-08-05

## Confirmed defects

1. Verification, GitHub, React Doctor, and review files could be digest-bound while their semantic contents contradicted trusted CLI gate values.
2. Unparseable evidence could pass when the digest matched.
3. Terminal completion did not replay specification and plan approval hashes.
4. The entire active specification directory was excluded from implementation fingerprints.
5. Review verdict vocabulary differed between the review schema and lifecycle gate.
6. Task-ID validation differed among task creation, worklog, schemas, and push proposals.
7. Pull-request E2E ran in both the Quality and E2E workflows.

## Design decision

Adopt a shared artifact-validation layer without introducing a second state machine:

```text
artifact file
  → JSON parse
  → canonical JSON Schema
  → semantic validator
  → derived gate values
  → digest / contract hash / HEAD / fingerprint checks
```

CLI status and count flags remain optional compatibility assertions. They never override report-derived values.

## Major changes

- Added `scripts/harness/artifact-validator.mjs` with zero-dependency synchronous Draft 2020-12 subset validation for runtime lifecycle artifacts and semantic validators for every evidence type.
- Added `scripts/harness/task-id.mjs` as the canonical task-ID contract.
- Added `harness/schemas/verification.schema.json` and a canonical fixture.
- Updated lifecycle gate schema to `1.1.0` and standardized review verdicts on `approved | changes_requested`.
- Updated `record-gate.mjs` to derive outcomes from reports.
- Updated every downstream transition and completion validation to replay approved contracts and all earlier evidence semantics.
- Limited lifecycle fingerprint exclusions to `gate.json`, `review.md`, `delegation.md`, `DONE.md`, worklog, and report storage.
- Added dynamic lifecycle artifact checks to `schemas:check`.
- Split non-E2E Quality verification from the dedicated E2E workflow and added `verify:all` for local full verification.
- Added independent-review finalization that binds task, HEAD, canonical diagnostic paths, actual report statuses, and SHA-256 digests without overwriting the verification-bound GitHub snapshot.
- Rejected symlinked evidence and incomplete approved-gate metadata before state is written.
- Documented exact evidence commit boundaries and migration behavior.

## Security and compatibility

- Invalid, stale, inconsistent, or unparseable evidence fails closed.
- React-relevant changes require a passing React Doctor report for the same task and HEAD.
- Passing GitHub evidence requires complete context, a pull request, at least one required check, and no blocked checks.
- Existing `1.0.0` gate files must be migrated before other lifecycle operations.
- Existing evidence reports must be rewritten to the current schemas or the task must return to the relevant phase; no legacy report is auto-promoted to passing.
