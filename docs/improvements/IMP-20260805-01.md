# IMP-20260805-01 — v10 consistency hardening

## Request

Audit the interaction between SDD/TDD-oriented v9 changes and production-learned v8 operational corrections, then remove contradictions and duplicated control definitions in four separately approved stages.

## Classification

- Type: architecture consistency, deterministic validation, CI integrity, auditability
- Scale: cross-cutting
- Initial risk: high

## Approved stages

1. Contract contradiction removal — completed.
2. Mechanical lifecycle and completion gates — completed.
3. Canonical local/CI verification and Draft 2020-12 schema validation — completed.
4. TDD evidence, worklog correction/input safety, and date policy — completed.

## Stage 1 result

- Capability manifest became the only normative source for Context7 fallback conditions.
- Documentation routing was separated from optional MCP browser routing.
- `DONE` was defined as a terminal operation rather than an active state.
- Historical PF-003 completion was preserved and labeled legacy.

## Stage 2 result

- Added `gate.json` as a non-duplicating approval/evidence index.
- Added transition and completion validators, semantic contract hashes, approved baseline, allowed-path checks, evidence SHA-256, rework, rebaseline, and explicit legacy migration.
- Resolved the remote-check cycle by allowing human-approved feature-branch transport after implementation evidence and before final verification/review.

## Stage 3 result

- Added canonical verification groups and made GitHub Actions call `verify:ci`.
- Added full harness-test discovery, Capability/Worklog/Lifecycle coverage, and CI duplication regression tests.
- Added Draft 2020-12 schema validation for canonical manifests, reports, structured outputs, and lifecycle templates.
- Fixed the Capability schema to accept the manifest `$schema` pointer.

## Stage 4 result

- Added required `test_discipline` structured output without adding TDD lifecycle states.
- Added semantic lifecycle validation: applicable TDD requires concrete Red/Green evidence; non-applicable TDD requires a concrete reason.
- Added append-only human correction entries for worklog history; original entries remain byte-for-byte unchanged.
- Added Worklog validation for actors, task IDs, verification values, lengths, control characters, Markdown/HTML structure, secret-like values, path traversal, missing evidence, symlink evidence, and unknown options.
- Added a shared time utility and explicit policy: machine evidence uses UTC ISO 8601, while `_active.md`, `DONE.md`, and Worklog file/ID dates use the operator's local calendar date. Worklog entries also record IANA time zone and UTC time.
- Final review bound verification to the exact recorded HEAD, made completion revalidate every downstream evidence digest, and aligned lifecycle task-ID validation with `task:new`.

## Independent review

The final review confirmed that SDD/TDD remain internal to the existing lifecycle, `gate.json` remains an evidence index rather than a second state source, CI uses the canonical verification entrypoint, Worklog remains separate from evidence reports, and no legacy Context7/GitHub MCP control path was reintroduced.

Findings discovered and fixed during review:

- HIGH: verification recorded `headSha` but did not compare it with the current HEAD. Fixed with exact-HEAD validation.
- HIGH: completion did not revalidate GitHub/React Doctor and all downstream evidence digests. Fixed by replaying every lifecycle validator before completion.
- MEDIUM: lifecycle gate task-ID schema was narrower than `task:new`. Fixed with one compatible task-ID pattern and a non-PF schema fixture.
- LOW: a realistic fake token literal in a test could trigger secret scanners. Replaced with runtime-generated test data.

Final status: no unresolved BLOCKER or HIGH findings.

## Verification summary

- 75 deterministic harness tests passed.
- 11 Draft 2020-12 schema cases passed with Python jsonschema fallback.
- Generated-rule synchronization, Capability checks, JSON parsing, MJS syntax, shell syntax, public-boundary checks, legacy MCP-control checks, and canonical-CI checks passed.
- Ajv execution, target-application lint/typecheck/build/E2E, real GitHub Actions, real Codex structured-output execution, and real React Doctor project diagnostics remain environment-dependent and were not claimed as executed.

## Packaging

The completed and reviewed result is packaged as Portfolio AI Harness v10.

## Erratum — 2026-08-05

A later adversarial consistency audit found that v10.0.0 could accept report digests while trusting contradictory gate values, did not replay approved specification/plan hashes at terminal completion, and did not semantically validate several evidence types. The historical verification result above is retained as the record of what was executed, but its conclusion is superseded by `IMP-20260805-02`.
