# IMP-20260806-01 — bootstrap-safe initial CI

## Request

Correct the v10.1.0 initial-commit failures in the `quality` and `e2e` jobs, where `actions/setup-node@v6` attempted npm cache resolution before a dependency lockfile existed.

## Classification

- Type: defect correction, CI bootstrap support, integrity hardening
- Scale: cross-cutting across workflows, scripts, tests, rules, and documentation
- Initial risk: high
- Approval: user response `承認` on 2026-08-06

## Confirmed cause

The package is an overlay and contains package fragments rather than a complete Node project. Its workflows nevertheless assumed that `package.json` and an npm lockfile existed on the first push. Removing only `cache: npm` would not solve the following `npm ci` requirement. A blanket skip for package-less repositories would create a CI bypass after the initial commit.

## Approved design

1. Add a deterministic `bootstrap | ready | invalid` npm project-state preflight.
2. Permit package-less operation only on the Git root commit when the harness overlay markers are present.
3. Fail closed on later metadata absence/deletion, package/lock mismatch, foreign or multiple lockfiles, and symlinked root metadata.
4. Invoke cached `setup-node` and `npm ci` only in the ready state.
5. Select React Doctor full scan for a root application commit and changed scan once a parent exists.
6. Document npm as the canonical CI package manager and preserve a reversible overlay installation flow.

## Security properties

- Bootstrap success is bound to the actual Git root commit and full checkout history.
- Deleting `package.json` and the lockfile on a later commit fails.
- Ambiguous package managers and symbolic-link metadata fail before dependency setup.
- Invalid states exit non-zero before third-party setup or application code execution.
- The canonical npm lockfile path is supplied explicitly to the cache key.

## Independent review

A separate post-implementation diff and package review found and corrected three issues before packaging:

1. Workflow invocation initially depended on the executable bit of the shell script after ZIP extraction; workflows now invoke it explicitly with `bash`.
2. A shallow clone could make a non-root commit appear root-like; the preflight now rejects shallow history and every relevant workflow uses `fetch-depth: 0`.
3. Any package-less root repository could have received the exception; bootstrap now also requires the canonical harness overlay markers.

No unresolved BLOCKER or HIGH finding remains.

Restore the v10.1.0 workflows and `verify:react` mapping, remove the new preflight and CI wrapper files, regenerate instruction outputs, and restore the previous documentation. Existing application `package.json` and lockfile are not rollback targets.
