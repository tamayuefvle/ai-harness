# Cursor IDE discovery writes

- ID: `IMP-20260814-01`
- Status: `done`
- Date: 2026-08-14
- Owner: human / Cursor

## Problem

Interactive Cursor IDE sessions do not set `HARNESS_CURSOR_ROLE`, so the policy hook treated them as read-only CLI workers and rejected discovery writes such as `docs/product/problem.md`.

## Proposal

Allow ordinary writes when `HARNESS_CURSOR_ROLE` is unset or empty. Continue to deny writes for every explicit non-`implementer` role, and retain generated-instruction and dangerous-command denials for all sessions.

## Acceptance

- Cursor IDE Agent mode can write approved product documents during `DISCOVERY` when the role is unset or empty.
- Explicit CLI `reviewer`, `read-only`, and unknown non-empty roles remain write-denied.
- CLI `implementer` ordinary writes remain allowed within its existing isolation contract.
- Generated instruction projections and dangerous commands remain denied regardless of role.
- Cursor Plan mode and Codex `npm run ai:discover` remain read-only.

## Verification

- `node --test scripts/harness/cursor-policy-hook.test.mjs`
- `npm run verify:harness`

## Outcome

The hook now distinguishes interactive IDE sessions from explicitly labeled CLI workers. Regression coverage verifies IDE discovery writes and the unchanged safety denials. User-facing workflow, security, migration, and release documentation describe the distinction in v14.9.1.
