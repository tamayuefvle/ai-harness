## Problem

v14.9.3 still described retired nested `AGENTS.md` routing in canonical rules. Codex preflight did not inspect project hook discovery, enablement, or trust. Cursor security-critical `preToolUse` hooks were fail-open. Planning fixtures duplicated full document bodies in JavaScript.

## Research

Codex app-server `hooks/list` reports project hook source, enabled state, and unmanaged `trustStatus` without reading user trust files. Linked Git worktrees may load `.codex/hooks.json` from the root checkout; semantic equality against the current worktree manifest is required. Cursor `failClosed: true` denies the action when the hook crashes, times out, or returns an invalid response.

## Proposal

- Replace nested AGENTS routing with provider-specific `CODEX.md` / scoped `.mdc` routing and add a stale-reference detector.
- Extend `codex:preflight` (schema 1.1.0) with a read-only `hooks/list` helper and fail-closed trust checks.
- Project Cursor `preToolUse` as `failClosed: true` and deny on hook implementation failure.
- Move planning seeds to `harness/templates/planning` and load them from disk.
