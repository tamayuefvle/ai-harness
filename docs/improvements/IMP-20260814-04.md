# IMP-20260814-04 — Provider instruction and hook trust consistency

## Problem

v14.9.3 passed its existing harness suite but still had four consistency gaps: canonical rules referenced retired nested `AGENTS.md`; Codex preflight did not verify current project hook trust; Cursor security-critical policy hooks were fail-open; and planning fixture content duplicated full seed documents in JavaScript.

## Research

Primary references used for the decision:

- OpenAI Codex hooks documentation: project hooks require project trust and unmanaged hook definitions require explicit trust for the current definition; `/hooks` is the interactive review surface.
- OpenAI Codex app-server protocol: `hooks/list` exposes project hook source, enabled state, current hash, and trust status and can be queried without mutating trust.
- Cursor hooks documentation: `failClosed: true` blocks on hook crash, timeout, or invalid output and is appropriate for security-critical hooks.
- Cursor permissions documentation: project permissions are best-effort controls and are not treated as the only security boundary.

## Proposal

1. Keep one shared root `AGENTS.md`; route Codex specialization through `CODEX.md` and Cursor specialization through scoped `.mdc`. Reject stale nested-`AGENTS.md` references in canonical rules.
2. Extend `codex:preflight` with read-only `codex app-server` `hooks/list` inspection. Require the repository project hook to be discovered, enabled, and trusted; for linked worktrees verify that the root-checkout hook manifest Codex actually loads matches the worktree copy; never write user trust or use a bypass as the normal fix.
3. Generate Cursor policy hooks with `failClosed: true` and keep CLI permissions, IDE approval/sandbox, hook policy, and worktree isolation as layered controls.
4. Move planning seed text into canonical `harness/templates/planning/*`; fixtures read those files rather than embedding duplicate document bodies.
